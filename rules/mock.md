# 시안 규칙

`/mock <UI 조각>`이 따르는 절차. 뼈대는 Emil Kowalski의 `prototype`이다(`_vendor/prototype.md`를 읽고 그 6단계를 따른다). 여기 적은 것은 덮어쓰는 점이다.

## 덮어쓰기

| prototype | 여기서는 |
|---|---|
| 첫 응답은 준비됐다는 인사만 | 인사 없이 바로 1단계. 첫 줄에 `재료: prototype · design/STACK.md · 축 3개` |
| 변형 이름은 영어 방향어("Quiet", "Editorial") | 한국어 방향어("조용한", "편집물 같은", "빽빽한"). "A안·B안" 금지는 같다 |
| 더미 내용은 제품다운 실제 문구 | 같다. **한국어** 제품 문구(실제 이름·숫자·날짜 형식). lorem ipsum, "홍길동" 반복 금지 |
| 토큰은 레포 것 | 같다. `_stacks/react/team.md`·`_stacks/design/team.md`가 채워져 있으면 그것이 상한. 모션은 `_stacks/animation/STACK.md` 기준(100회/일이면 없음, `ease-out`, 300ms 이하) |
| 5단계에서 표를 보이고 멈춤 | 같은 표 + `ask.md` 카드로 고르게 한다. 추천을 첫 번째에, 이유 한 줄 |
| 6단계 선택 시 반영 후 프로토타입 삭제 | 같다. 반영은 `/dev` 규칙(테스트 먼저, 최소 변경)으로. 확인하며 생긴 스크린샷·도구 폴더(예: `.playwright-cli/`, `output/`)도 같이 지운다. 사용자가 "남겨 둬"라고 하면 남긴다 |
| 피커는 `PICKER.md` 그대로 | 같다. `_vendor/picker.md`를 4단계에서 읽어 그대로 쓴다. 피커의 모양을 바꾸지 않는다 |

## 지키는 것

- 한 번에 조각 하나. "주문 목록 화면"처럼 넓으면 가장 효과 큰 조각 하나로 좁히고 말한다.
- 변형은 기본 3개, 요청하면 5개까지. 변형마다 축(배치·밀도·성격·모션·상호작용)을 한 구로 말할 수 있어야 한다. 색만 다른 변형은 변형이 아니다.
- 모든 변형이 실제로 동작한다(클릭, 모션, 상태). 죽은 버튼 없음.
- 프로토타입은 격리된 곳에만: dev 서버가 있으면 `/prototypes/<slug>` 같은 격리 라우트, 없으면 단독 HTML 파일 하나(브라우저로 바로 연다). 제품 코드를 건드리지 않는다.
- 보여 주기 전에 직접 돌려 본다: 변형마다 렌더되는지, 콘솔 오류가 없는지. 브라우저 도구가 있으면 변형마다 스크린샷.
- 표: 번호 | 변형 | 축 | 맞는 경우 | 비용. 끝에 피커 위치(URL 또는 파일 경로)와 넘기는 키.

## 후속 호출

- `/mock <조각> x5`: 변형 5개.
- `/mock riff <변형>`: 그 방향 주변으로 새 세트. 하네스는 유지.
- `/mock keep <변형>`: 반영하고 프로토타입 삭제. `keep <변형>, 남겨 둬`: 반영하되 하네스 유지.

## 하지 않는 것

- 탐색 중 제품 코드 수정.
- 사용자가 고르기 전에 반영.
- 같은 아이디어의 색·문구만 다른 변형.
