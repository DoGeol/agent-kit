# 글쓰기 규칙

`/write`가 따르는 규칙. 한국어가 기본. 사람이 읽을 글(기획서, 공지, 메시지, PR 본문)에 쓴다. 짧은 말투(caveman)를 쓰지 않는다.

## 먼저 정한다

독자, 목적, 형식(길이·구조), 어조. 요청에 없고 글에 영향이 크면 한 번에 묻는다(`ask.md`). 아니면 추정하고 첫 줄에 "독자: 운영팀, 길이: 10줄"처럼 적는다.

## 사실은 그대로

사실·수치·주장·범위를 더하거나 빼지 않는다. 원문이 있으면 원문의 뜻을 지킨다. 모르면 "확인 필요"라고 쓴다.

## 한국어 AI 티 (피할 것)

im-not-ai의 진단 규칙(MIT)에서 자주 걸리는 것만 추렸다. 더 정확한 교정은 im-not-ai의 `/humanize`.

| 패턴 | 대신 |
|---|---|
| 번역투 조사·구문: "~에 대하여/대해서", "~를 통해", "~에 있어서", "~와 관련하여", "~을 바탕으로", "~을 위해" 남발 | 동사로 직접: "논의한다", "로 한다", "에서" |
| 이중 피동 "~되어진다", "~지게 된다" / "~에 의해" 피동 | 능동 또는 단일 피동 |
| "가지고 있다" | "있다", "~이다" |
| "~할 수 있다" 반복 | 단정: "~한다" |
| 피동 진행 "~되고 있다" 반복 | "~한다", "~중이다" |
| "~은 명확하다/분명하다", "더 이상 ~않다", "단순한 X를 넘어 Y" | 뺀다. 사실만 쓴다 |
| 이중 조사 "~에서의", "~으로의" | 조사 하나 |
| 대명사 "그/그것/이는" 반복 | 생략하거나 명사 반복 |
| 억지 3항 나열, "A인가 B인가" 대구 반복 | 항목 수는 내용대로 |
| 접속부사 남발("또한", "그리고", "따라서"), 연결어미 뒤 쉼표 | 문장을 끊거나 접속사 없이 |
| 문장 길이가 다 비슷함 | 짧은 문장과 긴 문장을 섞는다 |
| 장식: 이모지, 굵게 남발, 제목만 있고 내용 없는 절 | 글로 말한다 |
| 챗봇 잔재: "물론입니다", "도움이 되셨길", 글 끝 요약 문장, 글 자체에 대한 설명 | 바로 본문. 끝나면 끝 |
| 사무적 동사: "~을 수행함/진행함/실시함", "~적 개선" | 동사 그대로: "고쳤다", "추가함" |
| 과장·영업 문구: "혁신적", "강력한", "완벽한" | 수치나 사실 |
| 과도한 완곡: "~일 수도 있을 것 같습니다" | "~이다", 모르면 "확인 필요" |

## 영어로 쓸 때

같은 원칙. 특히: "not X but Y" 대비 구조, 한 줄 마무리, 억지 3항, 대시 남발, 과장, 장식용 굵게, 챗봇 잔재.

## 끝에

im-not-ai가 설치돼 있으면 "`/humanize`로 다듬을 수 있습니다" 한 줄. 자동으로 돌리지 않는다. 초안은 사람이 먼저 본다.
