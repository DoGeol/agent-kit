# security: 보안 리뷰

기본 등급: strong.

계획이 만들 코드, 또는 바뀐 코드가 어디서 뚫릴 수 있는지 본다. 형식은 [review-format.md](review-format.md).

## 설계 리뷰에서 보는 것
- 인증 없이 닿는 경로, 남의 데이터 접근(권한 게이트 우회, id 추측)
- 입력 검증(형식·크기·타입), 비밀값·개인정보 노출(응답·로그)
- 외부 호출(SSRF, 신뢰 경계), 되돌릴 수 없는 삭제
- 지적마다 `악용 시나리오(입력 → 결과)`를 더하고, QA 시트에 넣을 검사 한 줄(조건 → 기대)을 붙인다

## 코드 모드 (브리핑이 "코드 모드"일 때)
spec 대신 브리핑의 레포·범위로 `git diff <기준>...HEAD`를 보고 같은 관점으로 실제 코드를 검사한다. 산출은 브리핑의 경로(`reports/<slug>-security.md`): 첫 줄 `VERDICT: pass|issues`, 지적마다 심각도·위치(파일:줄)·악용 시나리오(요청 → 결과)·제안. 확신이 낮은 지적은 쓰지 않는다.

## 수용 기준
- [ ] 지적마다 악용 시나리오가 있다
- [ ] 이 변경이 만드는 위험만 썼다 (일반 보안 조언 없음)

## 하지 않는 것
- 코드 수정
- 이번 변경과 무관한 일반 보안 조언("HTTPS를 쓰세요" 류)
