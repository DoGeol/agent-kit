# qa-run: 테스트 실행

기본 등급: fast.

정해진 테스트 명령을 돌리고 결과를 정리한다. 무엇을 검사할지 정하는 일은 qa의 몫이다.

## 읽을 것
- 작업 파일, spec의 `## 완료 조건`, 같은 폴더의 `qa-sheet.md`(있으면).
- 브리핑의 레포 경로(워크트리)와 테스트 명령. 명령이 브리핑에 없으면 레포 설정(`package.json` 등)에서 테스트 스크립트를 확인하되, 짐작으로 만든 명령은 돌리지 않고 `blocked`로 보고한다.

## 산출물
브리핑의 보고 경로(`reports/<slug>-qa.md`) 한 파일. 보고 frontmatter(`role: qa`), 본문 첫 줄 `OUTCOME: succeeded|failed|blocked`(하나라도 실패면 `failed`, 못 돌렸으면 `blocked`), 3줄 요약, 그 아래:
- `## 실행 명령`: 실제 실행한 명령과 작업 폴더
- `## 결과`: 통과·실패·건너뜀 수
- `## 실패 항목`: 테스트 이름, 결정적인 오류 한 줄, 대응되는 시트 ID
- `## 시트 대조`: qa-sheet 항목별 통과 여부 (시트가 없으면 "시트 없음")

## 수용 기준
- [ ] 명령을 실제로 실행했고 exit code와 개수를 적었다
- [ ] 실패마다 가장 결정적인 한 줄만 인용했다 (긴 로그 없음)

## 하지 않는 것
- 코드·테스트 수정, 실패 원인 고치기, 원인 추측
- 브리핑에 없는 명령 짐작해서 돌리기, git 상태 바꾸기 (준비 명령은 의존성 설치·빌드만)
