# UI 문구 (한국어)

영향: 중간. 짧은 문구 하나가 화면 전체의 이해를 좌우한다. 긴 글은 `/write`, 여기는 버튼·제목·오류·빈 상태 같은 짧은 문구.

## 규칙
- **버튼은 동사**로, 무엇이 일어나는지: "저장", "삭제", "보내기", "다음". "확인"·"예"·"제출" 금지. 두 단어 이내.
- **제목은 명사**로, 화면의 대상: "주문 목록", "결제 설정". 문장형 제목 금지.
- **오류**: 무엇이 안 됐나 + 무엇을 하면 되나. 사용자를 탓하지 않는다("잘못 입력하셨습니다" ✗ → "이메일 형식이 아닙니다. 예: name@example.com" ✓). 기술 용어(null, 500, timeout) 금지.
- **빈 상태**: 왜 비었나 한 줄 + 행동 하나. "데이터가 없습니다" ✗ → "아직 주문이 없습니다. 첫 주문을 만들어 보세요." ✓
- **확인**: 결과를 구체적으로. "정말 삭제하시겠습니까?" ✗ → "주문 3건을 삭제합니다. 되돌릴 수 없습니다." ✓
- 존댓말은 "~합니다/~하세요"로 통일. "~하실 수 있습니다", "~해 주시기 바랍니다"처럼 늘리지 않는다. 반말·"~요"체는 제품 전체가 그렇게 정했을 때만.
- 같은 것은 같은 말로: "삭제/제거/지우기" 중 하나만. 용어집이 있으면 따른다.
- 숫자·날짜·단위는 한 형식으로. "3개", "2026-10-21" 또는 "10월 21일", "1,234원". 영어 약어 대신 우리말("Save" ✗, "저장" ✓). 통용되는 영어(ID, URL, PDF)는 그대로.
- 느낌표·이모지·"성공적으로"·"~되었습니다"(이중 피동) 금지. "저장되었습니다" → "저장됨" 또는 "저장했습니다".
- 로딩 문구는 짧게: "불러오는 중…". 끝은 말줄임표 하나(…).
- 길이: 버튼 ≤ 6자, 토스트 ≤ 20자, 오류 ≤ 2문장, 빈 상태 ≤ 2문장.

## 틀린 예
- [확인] [취소] — 무엇을 확인하는지 모름.
- "요청이 성공적으로 처리되었습니다!"
- "에러가 발생했습니다 (500)".

## 맞는 예
- [삭제] [취소]. "저장했습니다". "서버에 연결하지 못했습니다. 잠시 뒤 다시 시도해 주세요."

## 이유
문구는 인터페이스다. 동사 버튼과 구체적 오류는 설명 없이 다음 행동을 알려 준다.
