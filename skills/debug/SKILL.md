# /debug

증상: 명령 뒤에 적힌 것. 비었으면 "무엇이 어떻게 잘못되는지 한 줄로 적어 주세요"로 멈춘다.

| 재료 | 쓰는 곳 |
|---|---|
| `_rules/debug.md` | 비밀값 가리기, 신호 먼저, 덮어쓰기, 보고 |
| `_vendor/systematic-debugging.md` | 뼈대: 원인 조사 → 패턴 → 가설·실험 → 구현 |
| `_rules/ask.md` | 3번 실패 뒤 묻기 |
| `_stacks/<스택>/STACK.md` | 레포 스택의 테스트 러너·검사 명령 |

## 절차

1. 첫 줄에 재료를 적는다: `재료: debug.md · systematic-debugging · 스택 python`.
2. `_rules/debug.md` 0·1절: 비밀값을 가리고, 이 버그에만 켜지는 신호를 만든다. 신호를 첫 줄 아래에 적는다.
3. `_vendor/systematic-debugging.md`의 4단계를 따른다. `_rules/debug.md` 2절의 덮어쓰기가 이긴다.
4. 고친 뒤 `_rules/debug.md` 3절: 신호가 초록인 것을 실제로 보이고 회귀 테스트를 남긴다. 보고 3줄.

## 하지 않는 것

- 신호 없이 고치기, 증상 가리기.
- 요청 밖 수정, 커밋.
