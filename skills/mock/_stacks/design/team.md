# 디자인 원칙

상태: accepted (범용 기본값)    마지막 검토: 2026-10-21    결정권: 사용자

범용 기본값이다. 어떤 제품에도 크게 틀리지 않는 원칙만 넣었다. 팀이 제품에 맞게 바꾸면 바뀐 것이 이긴다. 바꾸는 법은 `roles/designer/reference.md`. 원칙은 판단 기준, 규칙은 예/아니오로 확인하는 것, 토큰은 값의 위치다.

## 0. 범위와 우선순위
- 적용 대상: 이 레포의 모든 화면.
- 이 문서가 `STACK.md`와 역할의 일반 관점보다 우선한다.
- 원칙끼리 부딪히면: P1 > P2 > P3 > P4.

## 1. 원칙

### P1. 익숙함을 새로움보다 우선한다
- 문장: 기존 화면과 같은 패턴을, 더 나아 보이는 새 패턴보다 우선한다.
- 근거: 사용자는 화면을 배우러 오지 않는다. 같은 일은 같은 모양이어야 다음 화면을 설명 없이 쓴다.
- 지킨 예: 모든 목록 화면이 같은 필터·정렬·빈 상태 구성을 쓴다.
- 어긴 예: 한 화면만 카드형, 나머지는 표.
- 점검 질문: 이 요소와 같은 역할의 요소가 다른 화면에 있는가? 있으면 같은 모양인가?
- 상태: accepted (D-001)

### P2. 내용을 장식보다 우선한다
- 문장: 정보와 행동을, 꾸밈(아이콘·그라디언트·카드 중첩·애니메이션)보다 우선한다.
- 근거: 장식은 주 정보의 대비를 깎고 유지 비용을 늘린다. 뜻을 더하지 않는 요소는 빼는 쪽이 안전하다.
- 지킨 예: 상태는 문구 + 색, 아이콘은 문구를 대신할 때만.
- 어긴 예: 뜻 없는 일러스트, 목록 항목마다 그림자 카드.
- 점검 질문: 이 요소를 빼면 사용자가 잃는 정보나 행동이 있는가? 없으면 뺀다.
- 상태: accepted (D-001)

### P3. 한 화면에 주 행동 하나를 여러 행동보다 우선한다
- 문장: 화면마다 가장 강조할 행동 하나를 정하고, 나머지는 보조로 둔다.
- 근거: 강조가 둘이면 둘 다 약해진다. 사용자가 다음에 할 일이 한눈에 보여야 한다.
- 지킨 예: 폼 화면의 주 버튼 하나(저장), 취소는 보조 스타일.
- 어긴 예: 같은 크기·색의 주 버튼 셋.
- 점검 질문: 이 화면에서 주 스타일 버튼이 하나인가?
- 상태: accepted (D-001)

### P4. 모두가 쓸 수 있음을 보기 좋음보다 우선한다
- 문장: 키보드·스크린리더·저시력·터치에서 되는 것을, 시각적 완성도보다 우선한다.
- 근거: 접근성은 나중에 붙이기 어렵고, 지키면 모두에게 더 명확한 화면이 된다.
- 지킨 예: 대비 4.5:1, 포커스 표시, 색 외 표시(아이콘·문구), 터치 44px.
- 어긴 예: 회색 위 연한 회색 글자, 색만으로 구분하는 상태, `div`에 onClick.
- 점검 질문: 키보드만으로 이 화면의 모든 일을 끝낼 수 있는가? 색을 빼도 상태를 알 수 있는가?
- 상태: accepted (D-001)

## 2. 규칙
- R1 (P1): 같은 역할의 요소(버튼, 제목, 빈 상태, 날짜 표시)는 기존 컴포넌트를 쓴다. 확인: diff에 새 컴포넌트가 있으면 이유가 있는가.
- R2 (P2): 아이콘은 문구와 같이 쓰거나, 혼자 쓸 때 `aria-label`이 있다. 확인: 브라우저.
- R3 (P3): 화면마다 주 스타일 버튼은 하나. 확인: 브라우저.
- R4 (P4): 본문 대비 4.5:1, 터치 대상 44×44px, 포커스 표시 보임. 확인: 접근성 검사 도구 또는 브라우저.
- R5 (P1): 색·간격·글자 크기는 토큰만. 확인: diff에 임의 hex·px가 없는가.
- R6 (P2): 모든 데이터 화면에 기본·로딩·빈·오류 상태가 있고, 빈 상태에 다음 행동 하나가 있다. 확인: 브라우저에서 상태별 확인.
- R7 (P4): 모션은 `prefers-reduced-motion`을 존중하고 UI 모션은 300ms 이하. 확인: diff.

## 3. 토큰·컴포넌트 위치
- 토큰: 레포의 테마·CSS 변수 파일(없으면 `/design`이 첫 실행에서 찾아 여기 적는다).
- 재사용할 컴포넌트: 레포의 공용 컴포넌트 폴더(`shared/`·`components/ui/` 등).
- 상태 컴포넌트(빈·로딩·오류): 같은 폴더. 없으면 만들고 여기 적는다.
