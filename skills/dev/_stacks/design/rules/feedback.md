# 피드백 (토스트·인라인·진행)

영향: 중간. 행동 뒤에 반응이 없으면 사용자는 다시 누른다.

## 규칙
- 모든 행동에 100ms 안에 반응이 있다: 버튼 눌림 상태, 진행 표시, 결과.
- **토스트**는 행동 결과를 알릴 때(저장됨, 발송됨). 한 번에 하나, 3~5초, 되돌리기가 있으면 버튼 포함. 쌓이면 가장 오래된 것부터 사라진다.
- 토스트에 중요한 정보를 두지 않는다(사라진다). 오류·확인이 필요한 것은 인라인이나 대화상자.
- **인라인**은 그 자리의 상태(필드 오류, 저장 시각, 동기화 상태). 토스트보다 먼저 고려한다.
- **진행**: 1초 넘으면 진행 표시, 10초 넘으면 남은 시간이나 단계, 취소 가능하면 취소 버튼.
- 성공은 조용하게(토스트 하나 또는 상태 변화), 실패는 분명하게(인라인 + 할 수 있는 일).
- 같은 메시지를 여러 곳에 동시에 띄우지 않는다(토스트 + 배너 + 대화상자 금지).
- `aria-live="polite"`로 토스트를 읽어 준다. 오류는 `assertive`.

## 틀린 예
- 저장 버튼을 눌렀는데 아무 변화 없이 2초 뒤 저장됨.
- 오류를 토스트로만 띄우고 3초 뒤 사라짐.
- 성공 토스트 + 성공 배너 + 성공 대화상자.

## 맞는 예
- 저장 클릭 → 버튼 "저장 중…" → 완료 시 버튼 원복 + 토스트 "저장됨" 3초. 실패 시 폼 위에 인라인 "저장하지 못했습니다 · 다시 시도".

## 이유
피드백은 "들었다"는 신호다. 없으면 사용자는 시스템을 믿지 않고, 과하면 무시한다.
