# 폼

영향: 높음. 입력 화면은 사용자가 실패를 가장 많이 겪는 곳이다.

## 규칙
- 검증은 **필드를 떠날 때**(blur) 한 번, 제출할 때 전체. 타이핑 중에는 오류를 띄우지 않는다(이미 오류가 난 필드는 타이핑 중 지워질 수 있다).
- 오류 문구는 **그 필드 바로 아래**, 색 + 아이콘 + 문구. 무엇이 틀렸고 무엇을 하면 되는지("이메일 형식이 아닙니다. 예: name@example.com").
- 제출 실패 시 첫 오류 필드로 포커스를 옮기고, 화면 위에 요약(오류 n개)을 둔다.
- 필수 표시는 필수가 적을 때 필수에, 선택이 적을 때 선택에 "(선택)". 둘 다 많으면 필수에.
- 레이블은 항상 보인다. placeholder를 레이블 대신 쓰지 않는다.
- 제출 버튼은 하나, 폼 끝에. 제출 중에는 버튼을 비활성화하고 진행 표시. 두 번 눌림을 막는다.
- 긴 폼은 단계로 나누되 진행 표시와 "이전"을 둔다. 입력값은 단계를 오가도 남는다.
- 자동 저장이 있으면 저장 시각을 보인다. 없으면 떠날 때 "저장되지 않은 변경" 확인.

## 틀린 예
- 입력하는 동안 "비밀번호가 너무 짧습니다"가 깜빡임.
- 오류를 화면 맨 위에만 모아 두고 필드에는 표시 없음.
- placeholder "이름"만 있고 입력하면 레이블이 사라짐.

## 맞는 예
- 필드 아래 빨간 문구 + 아이콘, 제출 시 첫 오류로 포커스, 상단 "입력을 확인해 주세요 (2곳)".

## 이유
사용자는 오류를 "어디서, 무엇을" 고칠지 알아야 한다. 위치와 시점이 틀리면 같은 실패를 반복한다.
