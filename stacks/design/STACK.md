# design

화면을 새로 짜거나, 구성을 고르거나, 화면 코드를 리뷰할 때 읽는다. 읽는 순서: `team.md`(디자인 원칙. 있으면 우선하고 결정마다 원칙 ID를 적는다) → 아래 기준 → 걸리는 패턴 규칙 파일(`rules/`) → 상황별 파일.

## 패턴 규칙 (`rules/`, 걸리는 것만 읽는다)

| 패턴 | 파일 | 언제 |
|---|---|---|
| 폼 | `rules/forms.md` | 입력·검증·제출이 있는 화면 |
| 목록·표 | `rules/lists.md` | 정렬·필터·페이지·선택 |
| 빈·로딩·오류 상태 | `rules/states.md` | 데이터가 있는 모든 화면 |
| 내비게이션 | `rules/navigation.md` | 메뉴·탭·breadcrumb·뒤로 |
| 반응형 | `rules/responsive.md` | 좁은 화면·터치 |
| 대화상자·확인 | `rules/dialogs.md` | 모달·드로어·삭제 확인 |
| 피드백 | `rules/feedback.md` | 토스트·진행·인라인 상태 |
| UI 문구 | `rules/copy.md` | 버튼·제목·오류·빈 상태 문구 (한국어) |

## 상황별 파일

| 상황 | 읽을 것 |
|---|---|
| 새 화면의 방향(미감, 타이포, 템플릿 티 안 나게) | `vendor/frontend-design.md` |
| 컴포넌트를 만들 때(버튼·입력·토스트·메뉴): 상태 전이, 중단 가능, 키보드, 기본값 | `vendor/emil-design-eng.md`의 "Component Building Principles"와 "The Sonner Principles" 절만 |
| 라이브러리 고를 때(숫자 입력, 차트, 명령 팔레트, 드래그, 토스트 …) | `vendor/pick-ui-library.md` |
| 리뷰: 최악 데이터로 깨 보기 | `vendor/break-ui.md` |
| **실제 브라우저에서 확인**(상태별 스크린샷, 콘솔 오류, 요소 탐색) | `vendor/webapp-testing.md` (Playwright. `vendor/with_server.py`로 dev 서버를 띄우고 스크립트 실행) |
| "여기 뭘 움직이면 좋을까" (읽기 전용 제안) | `vendor/find-animation-opportunities.md` |
| 접근성·UX 점검 목록 | 원격 문서를 읽을 수 있으면 `https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md`. 없으면 아래 기준으로 |

## 기준

| 영역 | 규칙 |
|---|---|
| 간격 | 레포의 간격 스케일(보통 4 또는 8의 배수 토큰)만. 임의 px 금지 |
| 타이포 | 레포의 글자 크기 단계만. 본문 16px 이상, 줄 간격 1.4~1.6. 한 화면에 굵기 3단계 이하 |
| 색 | 토큰만. 새 색이 필요하면 밝은·어두운 테마에 같이 정의. 본문 대비 4.5:1, 큰 글자 3:1 |
| 상태 | 화면마다 기본·로딩·빈·오류 네 상태. 빈 상태에는 다음 행동 하나 (`rules/states.md`) |
| 위계 | 한 화면에 가장 강조할 곳은 하나. 주 행동 버튼은 하나 |
| 반응형 | 좁은 화면부터. 터치 대상 44×44px 이상. 가로 스크롤 금지 (`rules/responsive.md`) |
| 포커스 | 키보드로 모든 조작 가능. 포커스 표시 보임. 포커스 순서는 읽는 순서 |
| 색 외 표시 | 상태를 색만으로 나타내지 않는다(아이콘·문구 병행). 이미지·아이콘 버튼에 대체 텍스트 |
| 알림 | `aria-live`에는 꼭 들어야 할 변화만 (`rules/feedback.md`) |
| 문구 | 같은 것은 같은 말로. 버튼은 동사. 오류 문구에는 무엇을 하면 되는지 (`rules/copy.md`) |
| 장식 | 뜻 없는 아이콘·그라디언트·카드 중첩은 넣지 않는다. 필요한지 먼저 묻는다 |
| 최악 데이터 | 긴 이름, 한 글자, 빈 값, 0건, 999+건, 이모지, 다른 문자 체계에서도 깨지지 않게 |

## 구성 고를 때

같은 화면에 구성 2~3개(예: 테이블 / 카드 / 타임라인)를 축 이름과 장단점 한 줄로 비교하고 추천을 첫 번째에 둔다. 데이터 양·비교 빈도·주 행동이 결정 기준이다(`rules/lists.md`).

## 브라우저에서 확인할 때

1. `vendor/webapp-testing.md`대로 dev 서버를 띄운다(`with_server.py`).
2. 상태마다(기본·로딩·빈·오류) 스크린샷을 찍고 콘솔 오류를 본다.
3. 키보드만으로 주 흐름을 끝까지 가 본다. 좁은 폭(360px)에서 한 번 더.
4. 결과는 스크린샷 경로 + 발견한 것 목록으로.

## 하지 않는 것

- 사용자만 정할 값(개수, 기간, 형식)을 지어내기. 질문이나 가정으로.
- `team.md` 원칙과 다른 결정을 원칙 ID 없이 하기.
