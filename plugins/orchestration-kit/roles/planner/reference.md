# planner 참고: 계획과 최종 측정 시트 형식

[← planner 역할](../planner.md). Coordinator가 Task에 걸리는 절만 골라 명세의 역할 절 뒤에 붙인다.

## 계획 문서
1. 목표: 한 문단. 판정 기준 표(기준, 증거). 멈출 조건 목록
2. 하지 않을 것: 기능, 변경 금지 파일
3. 제약: 명세·저장소 값을 위치(파일:줄)와 함께 그대로
4. 바꿀 파일과 인터페이스: 표(파일, 수정/새 파일, 내용). 함수 시그니처와 결정 이유
5. 단계: 표(번호, 행동 하나, 확인 명령, 기대 결과). 결함을 일부러 넣어 새 시험이 실패하는지 보는 단계와 되돌리는 단계를 포함한다
6. 새 시험 설계: 서버·시간 제어 방법, 시험마다 순서와 단언
7. 시험이 다루지 않는 실패 모드: 표(실패 모드, 기존 코드 위치, 확인 방법) 5개 이상
8. 이 Task의 QA 시트 항목: PR 직전 최종 시트에 합칠 것
9. 남은 질문: 이미 답이 있음(근거) / 빌더가 정해도 됨 / 사용자만 답할 수 있음(질문, 추천과 이유, 가정한 값, 답이 다르면 바뀌는 단계)

## PR 직전 최종 측정 시트
- 한 PR에 들어가는 Task들의 QA 시트 항목을 모은다. 같은 명령·같은 기대는 하나로 합치고 출처 Task를 적는다
- 회귀 전체 실행(단위, e2e, 화면 비교)을 항목으로 넣는다
- 항목마다: ID, 출처 Task, 종류, 명령, 기대, 실행 등급(fast/default). 실제 결과 열은 qa가 채운다
- 시험 파일이 많아졌으면 시험 파일 검수 Task를 제안한다 (qa 참고 문서)
