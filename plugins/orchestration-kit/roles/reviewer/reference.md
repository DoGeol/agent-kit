# reviewer 참고: Task 종류별 절차

[← reviewer 역할](../reviewer.md). Coordinator가 Task에 걸리는 절만 골라 명세의 역할 절 뒤에 붙인다.

## 명세·계획 검토
- 입력은 명세 또는 계획·설계 문서의 경로다. 코드 diff가 아니므로 문서와 그 문서가 가리키는 요청 원문, 기존 정책·계약만 읽는다. 파일은 고치지 않는다.
- 다음 네 항목을 따로 판정한다 (통과 / 지적 있음 / 확인 못 함).

| 항목 | 질문 |
|---|---|
| 범위 | 요청의 완료 조건이 빠짐없이 들어갔나, 요청 밖 일이 들어갔나, 하지 않을 것이 적혔나 |
| 계약 | 새·바뀌는 인터페이스마다 소유자와 입력·출력·오류가 있나, 승인 대상 변경을 승인 대상으로 표시했나, 사용자 값을 계약에 박지 않았나 |
| 위험 | 되돌리기 어려운 변경, 동시 실행·공유 파일, 권한·샌드박스 밖 명령, 사용량이 다뤄졌나 |
| 검증 방법 | 수용 기준이 관찰 가능한가, 확인 명령과 기대가 있나, 결함을 넣어 실패하는지 보는 단계가 있나 |

- 지적마다 [reviewer 규칙](../reviewer.md)을 그대로 쓴다: 실패 상황, 위치(문서와 절), 고치는 법, 확신도. 확신도 80 미만은 판단 보류 목록에 이유와 함께 적는다.
- 출력: 네 항목 판정, 지적 목록(심각도 순), 판단 보류 목록, 확인하지 못한 범위. 마지막 줄은 `진행 가능? 예 / 아니오 / 수정 후`.
- 검토 횟수 상한, 생략 기준, 기록 형식은 [roles.md](../../policies/roles.md#명세계획-검토)가 정한다.
