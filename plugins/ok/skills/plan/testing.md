# 테스트 작성 기준 (QA 시트와 테스트 코드)

qa, 기능 세션, Coordinator(S 등급, `/ok:quick`)가 같이 쓴다. 목적은 구현 전에 경우를 따져 보는 것이다. 테스트를 많이 쓰는 것이 목적이 아니다.

## 1. 층 나누기

| 층 | 무엇을 | 언제 쓰나 |
|---|---|---|
| **단위** | 한 함수·모듈의 입력 → 결과. 외부(네트워크·파일·DB) 없음 | 분기·경계·계산 규칙이 있는 곳. 경우가 가장 많은 층 |
| **통합** | 두 층 이상이 맞물리는 계약: 실제 HTTP 요청 → 상태 코드·응답 모양, DB 쿼리, 컴포넌트 + API 호출 | 인터페이스(엔드포인트·이벤트·쿼리)가 새로 생기거나 바뀔 때 |
| **e2e** | 사용자 흐름 전체(화면 조작 → 서버 → 화면) | 핵심 흐름이 깨지면 안 되고, **레포에 이미 e2e 도구가 있을 때만** |

정하는 순서:
1. 규칙(조건 분기, 경계, 계산)이 있으면 **단위**로 검사한다. 같은 규칙을 통합에서 다시 검사하지 않는다.
2. 층 사이 연결(경로, 상태 코드, 직렬화, 권한 게이트)은 **통합**으로 검사한다. 인터페이스마다 정상 1, 오류 1.
3. **e2e**는 기능마다 핵심 흐름 1개까지. 도구가 없으면 시트에 `수동`으로 적고 확인 절차를 한 줄 쓴다.
4. 인프라·설정 변경(배포 설정, 환경 변수, 마이그레이션)은 가능하면 통합(설정을 읽어 실제로 뜨는지), 아니면 `수동` + 확인 명령.

## 2. 양 (서브태스크마다)

- 단위: 정상 1~2, 실제로 일어날 경계·오류 1~3.
- 통합: 인터페이스마다 정상 1, 오류 1. 권한이 걸리면 "남의 것·인증 없음" 1을 더한다.
- e2e: 기능마다 최대 1.
- 같은 경우의 변형(값만 바꾼 반복)은 쓰지 않는다. 일어나지 않을 조합은 쓰지 않는다.

## 3. QA 시트 형식 (`tasks/<slug>/qa-sheet.md`)

기능(spec `## 기능`의 F1, F2…)마다 절 하나, 표 하나.

```markdown
## F1 <기능 이름>
| ID | 서브태스크 | 층 | 종류 | 조건·입력 | 기대 결과 | 완료 조건 |
|---|---|---|---|---|---|---|
| F1-1-a | F1-1 저장소 | 단위 | 정상 | 완료 2개·미완료 2개에서 정리 | 2 반환, 미완료만 남음 | 완료 조건 1 |
| F1-1-b | F1-1 저장소 | 단위 | 경계 | 완료 0개에서 정리 | 0 반환, 되돌리기 기록 유지 | 완료 조건 3 |
| F1-2-a | F1-2 API | 통합 | 정상 | POST /api/todos/clear-done | 200 {removed: 2} | 완료 조건 1 |
| F1-2-b | F1-2 API | 통합 | 오류 | 숫자 아닌 id | 404 {error} | 완료 조건 4 |
```

- 완료 조건마다 최소 한 줄이 대응한다. 대응이 없는 완료 조건이 있으면 시트가 덜 된 것이다.
- `종류`: 정상 · 경계 · 오류 · 권한 · 회귀(기존 동작 유지).
- 기존 동작이 바뀔 위험이 있으면 `회귀` 한 줄을 넣는다.

## 4. 테스트 코드 규칙

- 테스트 이름에 시트 ID를 넣는다(예: `test_F1_1_b_clear_with_no_done_keeps_undo`, `test('F1-2-a …')`). 리뷰에서 시트와 맞춰 본다.
- 서브태스크마다 **테스트 커밋(`test: F1-1 …`) → 구현 커밋(`feat: F1-1 …`)** 순서. 테스트 커밋 시점에 실패하는 것이 정상이다.
- 동작(입력 → 결과)을 검증한다. 내부 함수 호출 순서·비공개 값에 묶지 않는다.
- 구현을 테스트에 맞추지 않는다: 테스트 입력 하드코딩, 테스트일 때만 도는 분기 금지. spec의 일반 동작을 구현한다.
- 테스트가 틀렸으면(spec을 잘못 읽음) 고치되 보고에 "바꾼 테스트와 이유"를 적는다. 통과시키려고 기대값을 약하게 바꾸지 않는다.
- 레포에 테스트 환경이 없으면 새 프레임워크를 들이지 않는다. 시트의 해당 줄을 `수동`으로 두고 보고에 확인 절차를 적는다.
- 레포의 기존 테스트 파일 배치를 따른다(단위와 통합이 같은 폴더면 같은 폴더).
