# 요구 정리 (plan 1.5단계)

작업 파일을 만든 뒤, spec을 쓰기 전에 Coordinator가 사용자와 한다. 간단 트랙은 하지 않는다. 답과 글은 모두 한국어.

목표는 **개발을 시작하기 전에 애매한 점을 최대한 없애는 것**이다. 애매함을 아래 채점표로 %로 재고, 기준 아래가 될 때까지 묻는다.

## 0. 먼저 읽기 (묻기 전에)

찾아보면 아는 것은 묻지 않는다. 아래를 먼저 읽고, 이미 정해진 것은 brief.md에 "확인됨(출처)"으로 적는다.

- `<P>/project.md`, `status.md`, `learnings.md`, 최근 `decisions/`
- 레포 CLAUDE.md·AGENTS.md, 요청과 관련된 코드·문서 (검색으로 3~5개 파일까지)

## 1. 애매함 채점표

축 7개, 가중치 합 100. 축마다 열린 점(정해야 할 것)을 적고, 축 상태를 매긴다: **확정 0 · 가정 0.5 · 미정 1**.

| 축 | 가중치 | 무엇이 정해져야 하나 |
|---|---|---|
| 목표 | 10 | 왜·누구를 위해. 성공하면 무엇이 달라지나 |
| 범위 | 15 | 포함·제외. 화면·API·저장·설정 중 어디까지 |
| 동작 규칙 | 25 | 입력 → 결과. 일치 방식·순서·계산·상태 변화 |
| 경계·오류 | 15 | 빈 값·없는 대상·중복·권한·실패 때 동작 |
| 화면·인터페이스 | 10 | 사용자가 보는 것, 이름·모양("상관없다"도 답이다) |
| 데이터·호환 | 10 | 저장 방식, 기존 동작·응답 유지, 되돌리기 |
| 완료 조건 | 15 | 확인할 수 있는 문장 |

- 축 상태: 열린 점이 모두 답을 받았으면 확정, Coordinator가 근거 있는 추정으로 채웠으면 가정, 하나라도 비었으면 미정.
- **애매함 % = Σ(가중치 × 상태)**. 예: 동작 규칙 미정(25) + 경계 가정(7.5) + 화면 미정(10) = 42.5%.
- 사용자가 "알아서", "상관없다"라고 답한 점은 **위임**이다. 확정으로 친다. brief에 "위임: Coordinator가 <고른 것>으로 정함"을 적는다.

## 2. 질문 (한 번에 하나)

- `AskUserQuestion`으로 **질문 하나**씩 묻는다. 선택지 2~4개, 첫 선택지는 추천안이고 라벨 끝에 "(추천)". 선택지마다 근거 한 줄.
- **다음 질문 고르기**: 가중치 × 상태가 가장 큰 축의 열린 점부터. 같으면 "가장 단순한 기본값이 틀릴 수 있는 곳"을 먼저 묻는다(예: 여러 단어 검색은 통째 일치인가 모두 포함인가, 지우면 되돌릴 수 있어야 하나, 결과를 화면에 어떻게 표시하나). 뻔한 것은 묻지 않고 가정으로 두고 5절 확인 때 보인다.
- 선택지에는 Coordinator가 떠올린 그럴듯한 다른 해석을 넣는다. 사용자가 "다른 뜻"을 말할 수 있게 둔다.
- 답마다 brief.md 해당 칸과 `## 애매함 기록` 표에 한 줄(`Q3 | 동작 규칙 | 답 요약 | 42.5% → 25%`)을 적는다.
- **세 번째 질문마다** 질문 본문 첫 줄에 "현재 애매함 n%(남은 큰 점: …)"를 붙여 사용자가 진행을 보게 한다.
- 기존 결정(레포 문서, hub decisions)과 충돌하면 그 사실과 출처를 질문에 넣는다.
- 답이 애매하면 추측하지 않는다. 그 점을 다시 좁혀 묻거나(같은 점은 2번까지) 미정으로 둔다.

## 3. 멈춤

아래 중 먼저 오는 것에서 멈춘다.

- **기준 도달**: 애매함 ≤ 10%(S·M) 또는 ≤ 5%(L), 그리고 `동작 규칙`·`완료 조건` 축이 미정이 아니다.
- **상한**: 질문 15개(L은 20개). 남은 점은 `## 미정`에 `? <질문>`으로 남기고 5단계 승인 카드에 같이 보인다.
- 사용자가 "그만", "이대로 진행"이라고 하면 멈춘다. 남은 점은 미정.

요청이 처음부터 분명하면(0절만으로 기준 이하) 질문 없이 5절 확인으로 간다.

## 5. 작게 확인

brief.md 요약(목표 1줄, 범위, 동작 규칙 핵심, 완료 조건, 가정·위임, 미정 개수, 애매함 시작→끝 %)을 보여 주고 `AskUserQuestion`으로 묻는다: "이대로 설계 문서를 쓸까요?" 선택지: "이대로 진행 (추천)", "고칠 점 있음". 고칠 점이 있으면 그 부분만 다시 묻고 고친다(이 확인은 질문 수에 넣지 않는다). 이 확인은 승인 관문이 아니다. 관문은 5단계 승인 카드 하나다.

## 하지 말 것

- 질문을 여러 개 한꺼번에 묻지 않는다.
- 코드·레포 파일을 고치지 않는다. 쓰는 파일은 brief.md 하나와 작업 파일의 `updated`뿐이다.
- 답을 지어내지 않는다. 모르면 미정. 가정은 가정이라고 적는다.
- %를 낮추려고 축 상태를 후하게 매기지 않는다. 답을 받지 않은 점은 확정이 아니다.
