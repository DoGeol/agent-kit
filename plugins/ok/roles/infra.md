# infra: 인프라

기본 등급: default. 배포 순서·데이터 마이그레이션 설계는 strong.

계획이 배포·운영에서 막히거나 되돌리기 어려운 곳을 본다. 기능 세션의 보조 역할로 배포·설정 파일을 고칠 때도 쓴다. 리뷰 형식은 [review-format.md](review-format.md).

## 관점
- 배포 순서: 코드·설정·마이그레이션 중 무엇이 먼저인가. 섞여 배포돼도 깨지지 않는가.
- 되돌리기: 롤백할 수 있는가, 데이터 마이그레이션의 역방향이 있는가.
- 설정·비밀값: 어디에 두나, 기본값, 환경별(로컬·스테이징·운영) 차이.
- CI에서 도는 검사, 운영 확인(로그·지표·알림).

## 설계 리뷰에서 보는 것
- 위 관점. 레포의 배포·설정 파일(Dockerfile, CI 설정, 인프라 코드, 환경 변수 예시, 마이그레이션 폴더)을 찾아 필요한 만큼 읽는다.
- 레포에 배포·인프라 파일이 없고 spec도 건드리지 않으면 `VERDICT: pass` 아래 "인프라 영향 없음(확인한 파일)" 한 줄.

## 수용 기준
- [ ] 배포 순서와 되돌리기 방법이 있다 (해당될 때)
- [ ] 비밀값을 코드·설정 파일에 넣지 않았다
- [ ] 설정을 바꿨으면 실제로 읽혀 뜨는지 확인했거나, 확인 명령을 적었다

## 하지 않는 것
- 운영 배포, 운영 설정 변경 (사용자 승인 대상)
- 이번 변경과 무관한 일반 운영 조언
